# WPFG Database

A reproducible database of **Water Plant Functional Group (WPFG)** classifications collated from existing classifications of wetland and aquatic plants.

The database brings together historical WPFG assignments, harmonises plant taxonomy, and synthesises the available evidence to provide classifications under both the **7-category and 10-category WPFG systems**. The two systems are treated as alternative levels of classification resolution rather than competing classifications.

The repository contains the source data and R workflow required to reproduce and update the database. Released versions of the database and supporting analytical files are archived separately on Zenodo.

## Database contents

The principal user-facing output is:

`WPFG_user_database_VerX.xlsx`

Its main worksheet, `WPFG_decision_database`, provides taxonomic information and separate 7-category and 10-category WPFG classifications.

For each system, the database reports the best-supported WPFG together with the evidence underlying that classification, including:

- best and second-ranked WPFG;
- support for each;
- the margin between the two;
- number of contributing sources;
- effective evidence after accounting for potential dependence among successive classifications; and
- fuzzy membership across all WPFG categories.

The database does not designate either the 7-category or 10-category system as preferable. Users can select the classification resolution appropriate to their application.

## Finding a taxon

### 1. Search `name_lookup`

Start with the `name_lookup` worksheet in `WPFG_user_database_VerX.xlsx`.

Search for the species name using the available taxonomic fields, including:

1. `recommended_name` — the preferred name for general use;
2. `accepted_name` — the APC accepted name, where available;
3. `scientific_name` — the scientific name returned by APCalign;
4. `suggested_name` — an alternative name returned by APCalign; and
5. `original_name` — a name occurring in one or more of the original source datasets.

Use `family`, `genus`, `taxon_rank` and `taxonomic_status` to confirm that the matched record represents the intended taxon.

### 2. Find the classification

Once the correct taxon has been identified, note its `taxon_id`.

Use `taxon_id` to locate the corresponding record in the `WPFG_decision_database` worksheet.

Additional worksheets provide the underlying species-level evidence, historical source assignments and genus-level information.

Genus-level information is provided as descriptive evidence only. It is not used automatically to assign WPFG classifications to species.

## Reproducing the database

The analysis uses an `renv` environment to record the R package dependencies used to generate the database.

After cloning the repository, open the RStudio project and restore the recorded package environment with:

```r
renv::restore()
```

The complete production workflow can then be run with:

```r
source("run_all.R")
```

`run_all.R` explicitly specifies:

```r
db_version
apc_data_type
apc_version
```

These identify the database release, input dataset and Australian Plant Census (APC) taxonomic resource used for that release.

The workflow deliberately uses explicit version settings rather than automatically selecting the newest input or taxonomic resource. This ensures that each database release can be reproduced using the same source data and taxonomic reference.

## Production workflow

`run_all.R` runs four scripts sequentially:

### `01_build_master_database.R`

Imports the source WPFG records, harmonises taxonomic names using `APCalign` and the specified APC resource, resolves within-source classifications, and constructs the taxonomic master database and audit trail.

### `02_wpfg_analysis.R`

Derives separate 7-category and 10-category species-level WPFG classifications, accounts for potential dependence among successive historical classifications, calculates fuzzy WPFG memberships, and produces the supporting classification analyses.

### `03_genus_analysis.R`

Describes conservation of WPFG classifications within genera. Genus-level results are kept separate from species-level inference and are not propagated automatically to unclassified species.

### `04_build_user_database.R`

Combines the taxonomic and analytical outputs into the final user-facing database.

The production workflow generates four versioned workbooks:

```text
plant_functional_group_master_VerX.xlsx
WPFG_classification_analysis_VerX.xlsx
WPFG_genus_analysis_VerX.xlsx
WPFG_user_database_VerX.xlsx
```

The principal release product is:

```text
WPFG_user_database_VerX.xlsx
```

The other three workbooks provide the supporting taxonomic, analytical and provenance information used to construct it.

## Validation

Validation is deliberately performed separately from the production workflow using:

```r
source("05_validate_WPFG_model.R")
```

This generates:

```text
WPFG_validation_VerX.xlsx
```

Validation includes checks of:

- WPFG category validity;
- fuzzy membership sums;
- duplicate taxon × source assignments;
- expected dependence-weighting behaviour;
- hierarchical relationships within the 10-category system; and
- sensitivity of classifications to the dependence-weight parameter.

The validation workbook is a quality-assurance and diagnostic product rather than part of the species classification procedure.


## Updating the database

A new database release is created explicitly rather than overwriting the existing release.

### 1. Create the new input dataset

Copy the current file in `data_in/`, add the new WPFG records, and save it with the next database version number.

For example:

```text
wpfg_lists_Ver1.csv
```

becomes:

```text
wpfg_lists_Ver2.csv
```

The input CSV contains four required columns:

- `original_name` — scientific name used in the contributing dataset;
- `WPFG` — WPFG assigned to the taxon;
- `source` — identifier for the contributing source, for example `Smith_2026`;
- `chrono` — integer identifying the chronological position of the source.

New sources should be assigned the next appropriate `chrono` value.

### 2. Identify the APC taxonomic resource

The workflow uses `APCalign` to harmonise names against the Australian Plant Census and associated taxonomic resources.

Identify the APC resource/version that will be used for the new database release. This version is recorded explicitly so that subsequent users can identify the taxonomic reference used during harmonisation.

### 3. Update `run_all.R`

Set the new database version and APC resource/version in `run_all.R`.

For example:

```r
db_version <- 2
apc_data_type <- "stable"
apc_version <- "YYYY-MM-DD"
```

The value of `db_version` determines both the expected input filename and the version labels applied to the generated outputs.

### 4. Run the production workflow

From the project root:

```r
source("run_all.R")
```

The workflow will expect:

```text
data_in/wpfg_lists_Ver2.csv
```

and generate corresponding `Ver2` workbooks in `data_out/`.

### 5. Validate the new release

Run:

```r
source("05_validate_WPFG_model.R")
```

Review the resulting validation workbook before releasing the updated database.

## Taxonomic provenance

Taxonomic harmonisation is performed using `APCalign` and an explicitly specified APC resource/version.

The workflow retains the original taxonomic information rather than replacing it. The master database therefore preserves original source names alongside harmonised taxonomic information and associated alignment metadata.

The database release is consequently tied to four reproducibility components:

```text
database version
        +
versioned input dataset
        +
APC resource/version
        +
R workflow and package environment
```
